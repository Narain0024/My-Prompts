# Smart Prompt Organizer — Product Concept

- **Category:** AI & Prompt Engineering
- **Provenance:** User-developed concept, recorded 2 November 2026; wording reconstructed from conversation context
- **Description:** Define a personal workspace for saving, organizing, retrieving, and improving prompts while learning from a user's prompt-writing patterns.
- **Purpose:** Turn a scattered prompt collection into a searchable, evolving knowledge base.
- **Tags:** `prompt-management`, `local-first`, `semantic-search`, `prompt-improvement`, `prompt-dna`

## Copy-ready prompt

```text
Act as a product strategist and experienced full-stack application architect.

Help me design and build a Smart Prompt Organizer: a personal workspace where I can save prompts, organize them intelligently, find prompts from my previous work, and improve rough ideas into clear, well-structured prompts.

## Core goals
1. Capture and store prompts with titles, descriptions, categories, tags, notes, and relevant project context.
2. Organize prompts so related items can be found without relying only on exact keywords.
3. Support full-text search, filters, favorites, collections, and project-based organization.
4. Maintain prompt version history so I can compare revisions and restore earlier versions.
5. Provide an AI-assisted prompt improvement workflow that turns rough instructions into structured prompts while preserving my intent.
6. Introduce a feature called Prompt DNA that analyses patterns in my prompt structure, detail, techniques, and iterations over time. It should help me understand how my prompting approach evolves rather than simply assigning an arbitrary score.

## Product principles
- Prioritize privacy and local control of personal prompt data.
- Keep the interface practical, fast, and easy to navigate.
- Make AI features transparent; do not imply that a feature works until it is implemented and tested.
- Preserve existing working functionality when extending the application.

## Expected output
Start with a clear product requirements document, user workflows, feature breakdown, data model, technical architecture, and phased development roadmap.
Identify assumptions and unresolved decisions instead of inventing requirements.
Then implement incrementally, with tests and verification at each stage.
```
