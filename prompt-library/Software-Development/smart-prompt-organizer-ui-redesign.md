# Smart Prompt Organizer — UI/UX Redesign Without Rebuilding

- **Category:** Software Development
- **Provenance:** User-approved collaborative design brief, 5 November 2026; polished from recorded requirements
- **Description:** Redesign the visual experience of an existing prompt organizer while preserving its working features and architecture.
- **Purpose:** Give an existing app a distinctive, warm, restrained visual identity without losing functionality.
- **Tags:** `ui-ux`, `redesign`, `react`, `design-system`, `regression-testing`

## Copy-ready prompt

```text
Act as a senior product designer and frontend engineer. Redesign the UI/UX of my existing application using the visual references and requirements I provide.

## Non-negotiable requirement
Redesign the existing application; do not rebuild it from scratch. Preserve all working functionality, existing routes, data flows, integrations, and user workflows.

## Visual direction
- Use a warm off-white / paper-inspired foundation.
- Combine charcoal text with deep teal and restrained mint accents.
- Keep layouts clean, minimal, and purposeful.
- Use a simple, compact navigation system.
- Use the mascot and app icon sparingly and consistently.
- Prefer clear hierarchy, useful spacing, readable typography, and practical information density.

## Avoid
- Generic AI-product gradients.
- Excessive glassmorphism.
- Oversized decorative illustrations.
- Unnecessary animations or visual effects.
- Replacing functional screens with mockups or placeholder pages.

## Existing functionality to preserve
Inspect the actual codebase and identify all existing features before editing. Preserve applicable functionality such as:
- Prompt creation, editing, search, filters, and version history.
- Semantic search and local AI/Ollama integration.
- Projects, collections, and knowledge-base workflows.
- Import/export and settings.
- Light and dark themes.

Do not assume every listed feature exists in the current branch; verify it first.

## Implementation workflow
1. Inspect the repository, routes, components, styles, and current behavior.
2. Summarize the existing architecture and identify the files that need changes.
3. Make a targeted implementation plan.
4. Create a safe backup or use version control before significant edits.
5. Implement the redesign in small, coherent stages.
6. Reuse existing components and data logic wherever possible.
7. Test every affected route and interaction after each stage.
8. Run the project's existing tests, type checks, and build.
9. Report changed files, preserved features, tests run, and any known limitations.

Do not delete, replace, or simplify working functionality merely to make the redesign easier.
```
